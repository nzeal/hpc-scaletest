# Partition-Aware Hardware Topology Detection

## Overview

HPC-ScaleTest v2.0.0 implements automatic, partition-aware hardware topology
detection. For any SLURM partition, the system programmatically determines:

- **CPU cores per node** - from SLURM queries or environment
- **GPUs per node** - from GRES configuration

And derives:

- **MPI ranks per node** = GPUs per node
- **CPU cores per rank** = CPU cores per node / ranks per node

This eliminates hardcoded values and site-specific constants, making the
framework portable across heterogeneous HPC systems.

## Example: Leonardo Booster

For partition `boost_usr_prod`:

```
Detected: 32 CPU cores per node, 4 GPUs per node
Derived:  4 ranks per node, 8 cores per rank
```

### Generated SLURM Directives (Full Node Allocation)

```bash
#SBATCH --ntasks-per-node=32
#SBATCH --gres=gpu:4
```

### Generated mpirun Commands

| Nodes | Command |
|-------|---------|
| 1 | `mpirun -np 4 --map-by ppr:4:node:PE=8 --report-bindings ./bind.sh $BINARY/iPIC3D os-stdin` |
| 2 | `mpirun -np 8 --map-by ppr:4:node:PE=8 --report-bindings ./bind.sh $BINARY/iPIC3D os-stdin` |
| 4 | `mpirun -np 16 --map-by ppr:4:node:PE=8 --report-bindings ./bind.sh $BINARY/iPIC3D os-stdin` |

### Formula

```
-np = (nodes) × (GPUs per node)
--map-by ppr:(GPUs per node):node:PE=(cores per rank)
```

## Detection Methods

The system uses three detection methods in priority order:

### 1. SLURM Environment Variables (Inside Job)

When running inside a SLURM job, these variables are used:

| Variable | Purpose |
|----------|---------|
| `SLURM_CPUS_ON_NODE` | CPU cores on current node |
| `SLURM_JOB_CPUS_PER_NODE` | CPUs per node (format: "32" or "32(x4)") |
| `SLURM_GPUS_ON_NODE` | GPUs on current node |
| `SLURM_GPUS_PER_NODE` | Requested GPUs per node |

### 2. sinfo Query (Login Node)

On login nodes, partition info is queried:

```bash
sinfo -p PARTITION -N -h -o "%c %G %m"
# Returns: CPUs GRES Memory
# Example: 32 gpu:a100:4 512000
```

### 3. scontrol Query (Fallback)

If sinfo fails, scontrol is used:

```bash
scontrol show partition PARTITION
# Parses: MaxCPUsPerNode, GRES

scontrol show node NODENAME
# Parses: CPUTot, Gres
```

## GPU Binding

GPU binding is handled via a script that uses `OMPI_COMM_WORLD_LOCAL_RANK`
to set `CUDA_VISIBLE_DEVICES`:

```bash
#!/bin/bash
# bind.sh - GPU binding script
if [ -n "$OMPI_COMM_WORLD_LOCAL_RANK" ]; then
    LOCAL_RANK=$OMPI_COMM_WORLD_LOCAL_RANK
elif [ -n "$MPI_LOCALRANKID" ]; then
    LOCAL_RANK=$MPI_LOCALRANKID
elif [ -n "$PMI_LOCAL_RANK" ]; then
    LOCAL_RANK=$PMI_LOCAL_RANK
elif [ -n "$SLURM_LOCALID" ]; then
    LOCAL_RANK=$SLURM_LOCALID
else
    LOCAL_RANK=0
fi
export CUDA_VISIBLE_DEVICES=$LOCAL_RANK
exec "$@"
```

## Portability

The same code works on different systems:

### Leonardo Booster
```
32 cores, 4 GPUs → 4 ranks/node, 8 cores/rank
mpirun -np N --map-by ppr:4:node:PE=8 ...
```

### LUMI-G
```
128 cores, 8 GPUs → 8 ranks/node, 16 cores/rank
mpirun -np N --map-by ppr:8:node:PE=16 ...
```

### DGX / 8-GPU Systems
```
128 cores, 8 GPUs → 8 ranks/node, 16 cores/rank
mpirun -np N --map-by ppr:8:node:PE=16 ...
```

### CPU-Only Systems
```
64 cores, 0 GPUs → 64 ranks/node, 1 core/rank
mpirun -np N --map-by ppr:64:node:PE=1 ...
```

## API Usage

### From Python

```python
from core.job_script_generator import (
    PartitionTopology, TopologyDetector,
    generate_job_script, get_mpirun_command
)

# Detect topology for a partition
detector = TopologyDetector()
topology = detector.detect("boost_usr_prod")

print(f"Detected: {topology.cpu_cores_per_node} cores, {topology.gpus_per_node} GPUs")
print(f"Derived: {topology.ranks_per_node} ranks/node, {topology.cores_per_rank} cores/rank")

# Generate mpirun command
cmd = get_mpirun_command(
    partition="boost_usr_prod",
    num_nodes=4,
    executable="$BINARY/iPIC3D",
    args=["os-stdin"],
    topology=topology
)
# Result: mpirun -np 16 --map-by ppr:4:node:PE=8 --report-bindings ./bind.sh $BINARY/iPIC3D os-stdin

# Generate complete job script
script = generate_job_script(
    partition="boost_usr_prod",
    num_nodes=4,
    executable="$BINARY/iPIC3D",
    args=["os-stdin"],
    job_name="ipic3d_scaling",
    account="my_account",
    env_setup=["module load cuda/12.0", "module load openmpi/4.1"],
    topology=topology
)
```

## Generated Job Script

For Leonardo Booster with 4 nodes:

```bash
#!/bin/bash
# =============================================================================
# SLURM Job Script - Generated by HPC-ScaleTest
# =============================================================================
# Partition: boost_usr_prod
# Detected topology:
#   CPU cores per node: 32
#   GPUs per node: 4
# Derived MPI mapping:
#   Ranks per node: 4 (1 per GPU)
#   Cores per rank: 8
# =============================================================================

#SBATCH --job-name=ipic3d_scaling
#SBATCH --nodes=4
#SBATCH --partition=boost_usr_prod
#SBATCH --ntasks-per-node=32
#SBATCH --gres=gpu:4
#SBATCH --account=my_account
#SBATCH --time=02:00:00
#SBATCH --output=./job_%j.out
#SBATCH --error=./job_%j.err
#SBATCH --exclusive

# Environment Setup
module load cuda/12.0
module load openmpi/4.1

# Set OpenMP threads to cores per rank
export OMP_NUM_THREADS=8

# GPU Binding Script
cat > bind.sh << 'BIND_EOF'
#!/bin/bash
if [ -n "$OMPI_COMM_WORLD_LOCAL_RANK" ]; then
    LOCAL_RANK=$OMPI_COMM_WORLD_LOCAL_RANK
elif [ -n "$SLURM_LOCALID" ]; then
    LOCAL_RANK=$SLURM_LOCALID
else
    LOCAL_RANK=0
fi
export CUDA_VISIBLE_DEVICES=$LOCAL_RANK
exec "$@"
BIND_EOF
chmod +x bind.sh

# Run Application
mpirun -np 16 --map-by ppr:4:node:PE=8 --report-bindings ./bind.sh $BINARY/iPIC3D os-stdin
```

## Documented Assumptions

The following assumptions are documented and justified:

1. **GPU jobs use 1 MPI rank per GPU**
   - This is the standard configuration for GPU-accelerated HPC codes
   - Rationale: Each GPU is typically managed by one MPI rank
   - Can be overridden if needed

2. **CPUs are evenly divisible by GPUs**
   - Most HPC systems have balanced CPU/GPU ratios
   - Integer division is used (truncates remainder)

3. **Full node allocation in SLURM**
   - `--ntasks-per-node` matches total CPUs (not MPI ranks)
   - Rationale: Ensures exclusive node access and proper resource accounting

4. **OpenMPI syntax with PE= for cores**
   - Uses `--map-by ppr:R:node:PE=C` syntax
   - Compatible with OpenMPI 4.x and later
